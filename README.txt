Парсер вакансий LinkedIn

Проект на Python, Django и PostgreSQL. Search собирает карточки вакансий, Details загружает описания и доступные сведения о компаниях. Оба этапа можно запускать отдельно. Результаты сохраняются в PostgreSQL и выгружаются в CSV.

Установка и первый запуск

1. На Windows 10 или 11 x64 скачайте репозиторий через Code → Download ZIP и полностью распакуйте его. Если репозиторий уже клонирован, откройте его папку.
2. Дважды щёлкните local.cmd. Во время первого запуска нужен интернет. Скрипт использует доступный Python 3.12 или 3.13 либо загружает Python. Он устанавливает зависимости, подготавливает локальный PostgreSQL, создаёт базу и применяет миграции. Права администратора Windows не нужны.
3. Оставьте окно запуска открытым. Когда откроется браузер, войдите с логином и паролем из консоли. На чистой установке логин — admin. Пароль создаётся автоматически и показывается один раз. Если браузер не открылся, скопируйте адрес из строки Django Admin в консоли.
4. При повторном запуске откройте тот же local.cmd и войдите с ранее созданными данными. Вакансии и настройки сохраняются.

Адрес Django обычно http://127.0.0.1:8000/admin/. Если порт 8000 занят, скрипт выбирает свободный порт и показывает фактический адрес. PostgreSQL и Django принимают подключения только с этого компьютера.

Запуск парсера

1. В разделе «Поисковые запросы» есть готовый запрос Python Developer / USA. Можно создать свой и указать страну.
2. Отметьте один активный запрос. В меню «Действие» выберите «Запустить поиск Search» или «Запустить поиск и обработку (Search + Details)» и нажмите «Выполнить».
3. Чтобы отдельно обработать сохранённые вакансии, откройте «Вакансии» и нажмите «Запустить обработку Details».
4. В разделе «Прогоны» можно включить автообновление и следить за счётчиками и ошибками.
5. В разделе «Вакансии» нажмите «Скачать все вакансии (CSV)». Экспорт включает все сохранённые вакансии независимо от открытой страницы и фильтров. Разделитель столбцов — точка с запятой.

Повторный поиск обновляет существующие записи по ID LinkedIn. Если LinkedIn ограничит доступ, уже собранные данные останутся в базе, а причина остановки появится в разделе «Прогоны».

Остановка и подключение к базе

Нажмите Ctrl+C в окне запуска, чтобы остановить Django. Чтобы также остановить локальный PostgreSQL, выполните local.cmd stop из папки проекта.

Для обычной работы pgAdmin 4 не нужен. Если требуется посмотреть таблицы, подключите pgAdmin 4 с параметрами PGHOST, PGPORT, PGDATABASE, PGUSER и PGPASSWORD из файла .env. Этот файл и локальная база не входят в репозиторий. Пароль администратора Django хранится в базе в виде хеша.

Результаты проверки

В живом прогоне Python Developer / USA сохранилось 1 000 вакансий. На следующей странице LinkedIn вернул HTTP 400. Контрольный запуск Details сохранил описания 10 вакансий. Запросы к профилям компаний получили HTTP 403, а один из последующих прогонов Details остановился на HTTP 429. Объём живого сбора 5 000–10 000 вакансий и проверка запросов через DevTools Network не подтверждены.

Отдельный синтетический прогон проверил обработку 5 000 вакансий и 50 компаний. Если у вас архив для проверяющего, CSV с предыдущим живым прогоном лежит в exports/linkedin-jobs-updated.csv и открывается отдельно. База после первой установки не содержит вакансий.
